# 本地文献数据库文档

> 版本：v1.0（2026-09-11）
> 适用范围：`uni-app/` 项目全部文献类文本数据（神祇、故事、生物、九界、卢恩符文、神器、编年史等）

---

## 1. 概述

项目中包含大量北欧神话文献信息。为方便**替换**和**更新**这些文本，项目建立了一个本地文献数据库（LocalDB），实现：

- **集中管理**：所有文献文本以"集合（collection）"为单位统一注册、统一读写
- **双通道更新**：
  - 出厂版本：直接编辑 `src/data/*.js` 种子文件，构建即生效
  - 本地热更新：运行时通过 `db` API 写入，立即生效并持久化，无需重新构建
- **版本自动管理**：通过内容哈希识别种子更新，新旧文本不会混杂
- **读写安全**：查询结果均为深拷贝，页面修改返回值不会污染数据库内部状态

## 2. 架构与数据流

```
页面（10 个）──import──> @/db 全局单例
                            │
                            ├── 集合注册（9 个）<── 种子数据 src/data/*.js（出厂版本）
                            │
                            ├── 查询：findAll / findById / find / getDoc …（深拷贝）
                            │
                            └── 写入：update / replaceCollection / importJSON …
                                      │
                                      └── 自动持久化 uni storage
                                          （H5 下为 localStorage，key: norse_local_db_v1）
```

## 3. 文件结构

| 文件 | 职责 |
| --- | --- |
| `src/db/localDB.js` | 数据库引擎（CRUD、持久化、种子哈希版本、导入导出） |
| `src/db/collections.js` | 集合注册：把 `src/data/*.js` 种子挂载为数据库集合 |
| `src/db/index.js` | 创建全局单例 `db`；开发环境挂载 `window.norseDB` |
| `src/data/*.js` | 文献种子数据（出厂版本），可直接编辑替换 |
| `tests/db.test.js` | 数据库单元测试（15 例） |

## 5. 快速上手

```js
import { db } from '@/db'

// 页面初始化时读取（每次导航都会拿到最新数据）
data() {
  return {
    gods: db.findAll('gods')
  }
}

// 详情页按 id 查询
onLoad(options) {
  this.god = db.findById('gods', options.id) || db.findAll('gods')[0]
}
```

## 6. API 参考

### 6.1 查询（均返回深拷贝）

| 方法 | 说明 | 示例 |
| --- | --- | --- |
| `db.findAll(name)` | 集合全部记录 | `db.findAll('gods')` |
| `db.findById(name, id)` | 按 id 查找，未找到返回 `null` | `db.findById('gods', 'odin')` |
| `db.find(name, queryOrFn)` | 条件查询；参数为对象（字段相等）或谓词函数 | `db.find('gods', { faction: '阿萨神族' })` |
| `db.findOne(name, queryOrFn)` | 条件查询单条，未找到返回 `null` | `db.findOne('gods', { name: '奥丁' })` |
| `db.count(name)` | 记录数 | `db.count('stories')` |
| `db.getDoc(name)` | 读取文档型集合 | `db.getDoc('worldTimelines').asgard` |

### 6.2 写入（自动持久化）

| 方法 | 说明 | 示例 |
| --- | --- | --- |
| `db.update(name, id, patch)` | 按 id 局部更新（浅合并）；未找到返回 `null`；不允许修改 `id` | `db.update('gods', 'odin', { description: '新文案' })` |
| `db.updateWhere(name, query, patch)` | 条件批量局部更新，返回更新条数 | `db.updateWhere('runes', { element: '火' }, { meaning: '火焰' })` |
| `db.insert(name, doc)` | 新增记录，缺 id 自动生成；id 重复抛错 | `db.insert('stories', { id: 'new-story', title: '…' })` |
| `db.insertMany(name, docs)` | 批量新增 | — |
| `db.remove(name, id)` | 按 id 删除，返回是否成功 | `db.remove('creatures', 'wolf')` |
| `db.replaceCollection(name, docs)` | **整体替换集合**（批量替换文献文本的主要方式）；校验 id 存在且唯一 | `db.replaceCollection('stories', newStories)` |
| `db.saveDoc(name, doc)` | 保存文档型集合（整体替换） | `db.saveDoc('dailyPicks', { god: 'thor' })` |

### 6.3 维护

| 方法 | 说明 | 示例 |
| --- | --- | --- |
| `db.reset(name?)` | 恢复种子数据；传集合名恢复单个，不传恢复全部 | `db.reset('gods')` / `db.reset()` |
| `db.exportJSON()` | 导出整库 JSON 字符串（备份/迁移） | `const dump = db.exportJSON()` |
| `db.importJSON(input)` | 导入 exportJSON 产物（字符串或对象），整体替换对应集合；返回 `{ applied, ignored }` | `db.importJSON(dump)` |
| `db.stats()` | 各集合概况（类型、数量、种子哈希、更新时间） | `db.stats()` |
| `db.collectionNames()` | 已注册集合名列表 | — |

## 7. 文本替换与更新的两种方式

### 方式一：编辑种子文件（推荐做大批量替换）

直接修改 `src/data/*.js`（如整段替换 `norseStories.js` 的故事文本），重新构建即生效。

**版本机制**：每个集合注册时对种子内容计算哈希（djb2）。种子文件变化 → 哈希变化 → 用户本地 storage 中的旧修改自动失效，恢复为最新种子。因此**不会**出现"新种子 + 用户旧修改"混杂的情况。

### 方式二：运行时更新（本地热更新，无需构建）

在控制台或代码中调用写入 API，修改立即持久化到本地 storage，**优先于种子**：

```js
db.update('gods', 'odin', { description: '临时替换的文案' })
db.replaceCollection('codexStories', importedStories)   // 整集替换
db.importJSON(backupJson)                               // 整库替换
```

**优先级总结**：

```
本地运行时修改  >  种子文件（src/data/*.js）
本地修改在种子文件更新后自动失效 → 回到最新种子
db.reset() 可随时手动清除本地修改 → 回到种子
```

## 8. 持久化说明

- 存储键：`norse_local_db_v1`（含版本号，未来结构升级可平滑迁移）
- 存储内容：`{ version, updatedAt, collections: { 集合名: { seedHash, data } } }`
- H5 端为 localStorage（约 5MB 上限，当前全部文献数据远小于此）
- 写入失败（如空间不足）时静默降级为内存模式，不影响页面运行
- **无 `uni` 全局对象的环境（如单元测试）自动降级为纯内存模式**，可通过 `globalThis.uni = { setStorageSync, getStorageSync }` 注入模拟存储测试持久化

## 9. 开发调试

开发模式（`npm run dev`）下数据库挂载在 `window.norseDB`，可在浏览器控制台直接操作：

```js
norseDB.stats()                                        // 查看各集合概况
norseDB.findById('gods', 'odin')                       // 查询
norseDB.update('gods', 'odin', { title: '新头衔' })     // 热更新文本（刷新仍生效）
norseDB.exportJSON()                                   // 复制整库备份
norseDB.reset()                                        // 一键恢复出厂
```

## 10. 新页面 / 新数据接入指南

**新页面读取现有集合**：

```js
import { db } from '@/db'
// data() 或 onLoad() 中：
this.stories = db.findAll('stories')
```

**新增文献集合**：

1. 在 `src/data/` 新建种子文件（数组每条记录必须含唯一 `id`；对象型数据用普通对象）
2. 在 `src/db/collections.js` 中注册：

```js
import { myLibrary } from '@/data/myLibrary.js'
// registerCollections 内追加：
.defineCollection('myLibrary', myLibrary)   // 数组型
// 或 .defineDoc('myConfig', myConfig)      // 对象型
```

3. 页面中 `db.findAll('myLibrary')` 读取即可获得种子编辑 + 本地热更新双通道能力

## 12. 常见问题

**Q：运行时修改的文本，什么时候会丢？**
A：两种情况——① 对应集合的种子文件被更新（哈希变化，本地修改让位给新种子）；② 调用 `db.reset()`；③ 用户清除浏览器存储。因此运行时修改适合"本地热更新/临时文案"，正式内容请落回种子文件。

**Q：为什么我改了 `db.findAll()` 返回的对象，数据库没变？**
A：查询返回深拷贝是设计行为，防止页面误改数据库。要修改请使用 `db.update()` 等写入 API。

**Q：页面会实时响应数据库变化吗？**
A：页面在导航（`data()` / `onLoad`）时从数据库取数，因此重新进入页面即可看到最新文本；无需刷新整个应用。

**Q：`runes`（简版）、`dailyPicks` 目前没有页面使用？**
A：v1.2 起两者已从数据库注销，种子文件仅作保留（runes 简版供测试引用，dailyPicks 已被档案页"今日符文"哈希算法取代）。`codexStories`（v1.1）与 `codexCreatures`（v1.2）均已分别合并入 `stories` 与 `creatures`。
