## 1. 产品概述

### 1.1 背景与机会
北欧神话中文数字产品普遍是两类：严肃资料站（维基类，查询强、无留存）或换皮小游戏（娱乐强、知识弱）。两者之间存在空档：**以收集游戏为壳、以权威资料为芯的轻学习产品**。本项目以此切入。

### 1.2 定位声明
**交互性北欧神话资料集成与学习小程序**——本质是一个**知识类休闲小游戏**：边玩边学，附带收集与解锁图鉴的过程。

### 1.3 设计哲学
- **收集感与解锁惊喜是引擎，知识是伴生奖励**（图鉴式学习，非教材式学习）
- 知识在"惊喜时刻"被阅读（解锁知识卡），而非被布置（课程/作业）
- 一天 3 分钟也有事可做（每日钩子），但无打卡焦虑（无强制通知、无失败惩罚）

### 1.4 目标用户画像
| 画像 | 描述 | 核心诉求 | 对应功能 |
|---|---|---|---|
| P1 神话爱好者（核心，约20%） | 看过《埃达》或相关影视，想查证细节 | 权威资料、谱系、出处 | F1 资料集成、关系网络、编年史 |
| P2 休闲收集玩家（主力，约70%） | 玩图鉴收集类游戏，对神话有好感但不系统 | 收集进度、解锁惊喜、每日小目标 | F2 碎片经济、F3 每日系统、F5 小游戏 |
| P3 陪读/亲子（约10%） | 家长带孩子读神话故事 | 故事长卷、安全无内购 | F1 故事、明确无商业化 |

### 1.5 核心体验循环
```
游玩（测验/翻牌/供奉/阅读）
   → 产出（碎片掉落 / 眷顾增长）
      → 解锁（图鉴条目 / 神谕事件 / 成就）
         → 知识伴生（解锁知识卡被阅读）
            → 收集欲（完成度环 n/16 增长）
               → 回到游玩（含每日钩子拉回）
```
所有功能必须能挂到这个循环上；挂不上的（如纯装饰性内容）降级为 P2。

### 1.6 产品边界（明确不做）
- ❌ 课程式学习路径、导学关卡、打分体系
- ❌ 错题本、间隔复习等备考类功能
- ❌ 账号云同步、多人对战、社交系统
- ❌ 广告、内购、任何商业化组件
- ❌ UGC（用户生成内容）——内容只来自编辑审核的种子数据

## 2. 用户体验设计

### 2.1 用户旅程
- **D0（首次）**：splash → 档案登记（或访客）→ 首页 → 顺手点进一个神 → 发现眷顾卡 → 供一次品 → 掉落第一片碎片 → 看见图鉴完成度环启动。目标：3 分钟内触达核心循环。
- **D1**：每日签到（三档奖励之一）→ 昨天没集齐的条目差几片 → 翻牌/测验补片。
- **D7**：多数直接可见条目已解锁 → 碎片合成条目推进中 → 触达第一个条件解锁隐藏条目 → 眷顾某神接近满级。留存动力：完成度环 + 隐藏条目 + 连签。

### 2.3 设计语言规范（不可漂移项）
- **色彩**：金色强调 `#C6A15B`（`--accent`），暗色卡片底，主题两套：夜幕（默认）/ 羊皮卷（浅色）
- **字体**：中文衬线标题 + Cinzel 西文碑文（降级 Georgia）
- **形状**：圆角卡片（16–32rpx），金色描边用于可交互强调
- **文案体裁**：箴言体（"你的言辞被独眼者听去了一半"），禁口语化
- **揭晓层**：所有解锁/成就/知识卡统一金色碑文全屏层（ᛟ 印记 + 标题 + 箴言体描述 +「铭记于心」类按钮）
- **数值显示**：一律整数（禁止 7.5 类小数）；掉落用聚合 toast「拾得 xx 碎片 ×n」，不刷屏

## 3. 功能需求详述

> 每个模块含：目标 / 规则 / 状态机 / 边界与异常 / 验收标准 / 实现状态。
> 实现状态标记：✅ 秒哒 v18 已上线；📍 仅本地版；⏳ 规划中。

### F1 资料集成（内容底盘）
**目标**：权威、成体系的北欧神话内容库。
**内容清单**：
| 类目 | 数量 | 备注 |
|---|---|---|
| 诸神 | 13 | 阿萨 7 / 华纳 3 / 巨人血统 3；字段：司职/象征/圣物/五维属性(智慧·战斗·魔法·权威·命运)/关系网络 |
| 生灵 | 9 | 灾厄/巨兽/精怪；含危险等级、喜恶（供羁绊联动） |
| 法器 | 7 | 冈格尼尔、妙尔尼尔等 |
| 故事 | 9 | 创世→诸神黄昏主线，卷轴式排版 |
| 卢恩符文 | 24 | 老弗萨克三组八文，含名/音/含义 |
| 九界 | 9 | 世界树三层结构 |
| 编年史 | — | 神话时间线 |
**规则**：内容数据以本地版 `src/data/` 种子为唯一源（双版本对齐原则，见 §4.4）。
**边界**：未解锁条目详情页显示剪影 +「尚未收录」+ 解锁条件。
**验收**：13 神详情页均含眷顾区块与差异化供品；搜索/筛选可用；未解锁条目不可看正文。
**状态**：✅（出处小字 sources ⏳ P2；诺伦/女武神/巨人族谱补厚 ⏳ P2）

### F2 图鉴解锁与碎片经济（核心引擎）
**目标**：把"看资料"变成"收集资料"。
**三层解锁模型**：
| 层 | 条目数 | 机制 |
|---|---|---|
| 直接可见 | 6 | 开箱即看（芬里尔、斯莱普尼尔、欧德姆布拉、冈格尼尔、妙尔尼尔等标志性条目） |
| 碎片合成 | 9 | 每条 3–4 片，集齐后「合成解锁」→ 金色碑文知识卡（条目名+箴言短文+「收录于图鉴」） |
| 条件解锁 | 3 | 隐藏条目：列表显示 ？？？剪影 + 条件提示 |
**条件解锁配置**：
| 条目 | 解锁条件 |
|---|---|
| 海拉（冥界女王） | 任一神祇眷顾满级（100） |
| 血鹰纹章 | 洛基供奉累计 20 次 |
| 密米尔头颅 | 知识测验正确率 ≥75% |
**状态机**：`locked-hidden → (条件触发，自动) → unlocked`；`locked-shard(n/m) → (碎片集齐+用户点击合成) → unlocked`。
**碎片产出渠道**：见 §5.2 经济表。
**边界与异常**：碎片掉落目标只分配给"未集齐"条目（全部集齐后掉落降级为无目标提示）；聚合掉落修复超发边界（同点双读快照问题，已修）；合成按钮在碎片未满时不渲染。
**验收**（全部来自实测）：测验答对掉片、供奉概率掉片、每日首访 +1、合成出知识卡、完成度环 +1、档案切换碎片进度独立、刷新后状态保持。
**状态**：✅（本地版回灌 ⏳ P0）

### F3 每日系统
**目标**：一天 3 分钟的回访理由，无焦虑设计。
**签到**（档案页，完成度环下方）：
- 三档随机：50% 碎片×2 / 30% 点亮随机未参详符文 / 20% 随机神眷顾 +5
- 兜底：符文全参详或眷顾全满时自动降级，不空签
- 连签计数，断签重置为 1；同日重复在入口与 reducer 双重拦截
- 签到后按钮灰置「已领取」+ 当日日期
**每日首战双倍**（测验）：
- 当日首次**交卷**（点「查看结算」）时消耗资格；中途退出不消耗
- 双倍局：答对 2 片/题、通关 +4（普通：1 片/题、+2）
- 标识：列表页 + 答题页 sticky 页头金色徽标「今日首战 · 掉落翻倍」，全程显示
**每日限产**：翻牌每日仅前 3 局产出碎片（牌运胶囊 n/3，跨天重置）。
**每日首访**：当日首次进入应用 +1 碎片（按本地日期 key 去重）。
**状态机**：`未签 → 已签(当日)`、`双倍可用 → 已消耗`、`牌运 n/3`，均跨天（本地 ISO 日期，不受时区偏移）重置。
**验收**：签到三档文案与实际效果一致、断签重置、双倍只在首局、牌运耗尽后胜利面板提示「明日再来」。
**状态**：✅（本地版回灌 ⏳ P0）

### F4 角色互动系统
**神祇眷顾（favor，双版本）**：
- 四阶段：立于神前(0) → 蒙神注视(30) → 神恩加身(60) → 眷顾之人(100)
- 供品：基础 +5；命中该神偏好 ×1.5 → 8（Math.round 取整，禁小数）；按司职差异化（奥丁=蜂蜜酒/诗歌残页/卢恩刻痕/渡鸦之羽…）
- 神谕事件：跨 30/60/100 阈值弹金色碑文全屏层，每神 3 条独立文案；满级后提示「已达最高眷顾」
- 数据按神祇 id 独立持久化
**生物羁绊（bond，📍仅本地版）**：与眷顾同构四阶段（初识/试探/信任/同行），likes ×1.5、dislikes ×0.5（下限 1），`bondEvents` 数据覆写模板；特殊类型：spirit（精灵微光结契）、abyss（耶梦加得高危观测，含 riskLevel/sanityLoad 独立体系）。
**验收**：13 神眷顾卡全量渲染、偏好加成取整、神谕文案每神不同、满级庆祝。
**状态**：✅（秒哒眷顾 + 本地 bond；本地 favor 引擎已建，UI 已接）

### F5 小游戏
**知识测验**：16 题库随机 8 题，涵盖诸神/九界/生灵/法器/传说/符文；单选、判题反馈、结算称号；掉落见 §5.2。
**符文记忆翻牌**（/memory-game）：
- 24 符文随机抽 8 对 → 4×4 牌阵；3D 翻牌 300ms；不匹配 900ms 翻回，期间 locked 拦截第三张
- **含义伴生**（核心学习目的）：每翻一张，牌阵下方显示「符文名 · 音 · 含义」
- 奖励分档（按翻牌次数 m，理论最少 16）：m≤22 → 3 片；23≤m≤32 → 2 片；m>32 → 1 片；每日首胜 +1
- 每日前 3 局产出；最佳纪录（最少次数/最快用时）随档案隔离
**卢恩占卜**：箴言体三符文抽取（轻功能，不掉落）。**神格匹配**（📍本地版）。
**验收**：配对判定按 runeId、900ms 内不可连点、分档边界（22→3，23→2）、牌运胶囊、纪录更新与「新纪录」徽标。
**状态**：✅

### F6 用户与档案体系
**目标**：本地多账号，进度互不串味（无后端、无上传）。
**规则**：
- 档案名 2–16 字符唯一；密码 ≥4 字符；SHA-256(salt+password) 哈希存储（非安全上下文降级 djb2+salt），明文绝不落盘
- LoginGate：无任何会话（含访客）禁止直达内容页
- 登录页：ᛟ 碑文风，「进入档案/新建档案」双模式，已建档案 chips（点选预填、✕ 封存二次确认「全部进度将随之消散，无法找回」），「以访客身份继续」
- 记住上次档案名（预填）；无档案时默认注册模式
- 设置页账户区：当前档案名 + 切换/新建 + 登出
**快照隔离**：见 §4.3 矩阵。
**验收**：注册→自动登录→首页；档案 A/B 进度互不串味；登出后快照保留；封存删除档案与快照。
**状态**：✅（双版本）

### F8 氛围系统

**验收**：开关开→网络请求 mp3 206；音量滑杆即时；翻页不中断不重复；刷新状态保持。

## 4. 数据模型与持久化规范

### 4.1 本地版
- **LocalDB（内容层，`src/db`）**：9 集合 realms/gods/stories/creatures/runeDetails/artifacts/timeline/worlds/worldTimelines；种子 `src/data/*.js` 出厂 + diff 持久化（种子哈希变更自动失效本地 diff）
- **StateDB（状态层，`src/state`）**：命名空间分片 `norse_state_v2::<ns>`；关键命名空间：progress / bond / favor / game / settings / users / session
- 引擎：`src/interactions/`（bond/favor/achievements）、`src/auth/user.js`

### 4.2 秒哒版（localStorage keys）
- `nordic-session`（当前会话/访客）、`nordic-settings`（musicOn/musicVolume/theme/sfxOn）
- `nordic-daily-shard-<date>`（每日首访去重）
- ArchivePayload（档案快照：进度/眷顾/碎片/签到/翻牌纪录，随登录体系换入换出，400ms 防抖落盘）
- `src/lib/daily.ts`：本地 ISO 日期工具（跨天判定不受时区偏移）

### 4.3 快照隔离矩阵
| 数据 | 随档案隔离 | 全局共享 |
|---|---|---|

### 5.2 碎片经济产出表
| 渠道 | 普通 | 每日首战/首胜 | 日上限 |
|---|---|---|---|
| 测验（8 题） | 答对 1 片/题 + 通关 2 | 答对 2 片/题 + 通关 4 | 无硬上限（题库 16 题） |
| 供奉 | 30%/50% 掉 1 片 | — | 无 |
| 每日首访 | +1 | — | 1 |
| 翻牌胜利 | ≤22 次→3 / ≤32→2 / >32→1 | 首胜 +1 | 前 3 局产出 |
| 每日签到 | 50% 概率 ×2 | — | 1 次 |
**单日理论产出上限**：约 2(签到)+1(首访)+3×4(翻牌满绩效)+双倍测验(全对 20)+供奉若干 ≈ **35+ 片**；单个合成条目需 3–4 片 → 健康节奏下每日可解锁 1–2 条。
**调参规则**：改动上表任何数值须在变更记录登记原因与预期影响。

## 7. 质量保障与发布验证协议

### 7.1 测试策略
- **本地版**：vitest 全量（当前 125+ 用例：bond/favor/user/achievements/state/db…）+ `npm run build`
- **秒哒版**：平台 lint（tsgo/biome/check.sh/tailwind/testBuild）
- **线上行为验证**：无头浏览器（Playwright + 缓存 Chromium）实测生产站；测试资产 `/tmp/web-audit/`（路由走查/登录/眷顾/碎片/签到/翻牌全套脚本，可复用）

### 7.2 发布验证协议（强制）
> **publish SUCCESS ≠ 线上生效**。已三次实测遇到传播延迟（+7.5 小数、BGM 合成音源文案、runes 面包屑）。
1. publish 返回 `RELEASE_SUCCESS + CODE_SYNC_SUCCESS` 后，**必须**做两件事之一：
   a. grep 线上 JS bundle 中的新特征字符串；b. 行为实测（无头浏览器断言）。
2. 行为异常时先怀疑旧构建，**禁止**在状态非 FAILED 时重复 publish。
3. 秒哒 chat 本地 CLI 超时不代表任务失败：云端照常执行，用 trajectory/fetch-trajectory 轮询拿结果，**不要重发指令**。

### 7.3 验收 checklist 模板
功能上线前逐项打勾：lint 绿 / 单测绿（本地版）/ 线上 bundle 含新特征 / 行为断言通过 / 档案隔离与刷新保持 / 回归（眷顾卡、BGM、零 pageerror）。
